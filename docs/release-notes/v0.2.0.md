## Highlights

v0.2.0 replaces the two-container (Caddy + FastAPI) deployment with a **bundled
single-container image** and rewrites `magpie-deploy.sh` around it. Upgrades from
v0.1.x are automatic: the installer backs up, swaps, asserts, and rolls itself back
on failure. `/data` is untouched (bind mount, no transform).

The one case that requires operator action before upgrading is an install that used
magpie's **built-in TLS** (`TLS_MODE=auto|manual`) -- see below.

## Bundled, HTTP-only deployment model

- The image published as `ghcr.io/southwestccdc/magpie:0.2.0-bundled` runs Caddy and
  uvicorn under one non-root supervisor and fails fast if either dies. The installer
  and the canonical `docker-compose.yml` consume that tag.
- The container serves **plain HTTP on :8080 only** and is expected to be fronted by
  your own reverse proxy for TLS. Nothing in the container terminates TLS anymore.
- If magpie is fronted (it now always should be) and you use CIDR allow-listing or
  care about client IPs, set `MAGPIE_TRUSTED_PROXIES` to your proxy's address/CIDR.
  The `update` gate hard-fails a fronted install with an empty value.
- `magpie:0.2.0` / `:latest` remain the **two-container** image for the whole 0.2.x
  line, so every 0.2.x cut stays installer-compatible. Making bundled the primary
  tag (and retiring the two-container Dockerfile) is a v0.3.0 change.

## Built-in TLS is deprecated

- These installer flags now warn and no-op, and will be **removed in v0.3.0**:
  `--tls-mode auto|manual`, `--domain`, `--tls-cert`, `--tls-key`, `--acme-server`,
  `--https-port`.
- An existing install with `TLS_MODE=auto|manual` **hard-fails `update`**. Put an
  external TLS proxy in front of magpie first, then re-run with
  `--accept-builtin-tls-removed` to acknowledge and continue.

## Upgrading from v0.1.x

1. Read the built-in TLS section above; if it applies, front magpie with your own
   proxy before upgrading.
2. Set `MAGPIE_TRUSTED_PROXIES` if magpie sits behind a proxy.
3. Run `sudo magpie-deploy.sh update`. It backs up, swaps to the single-service
   topology, asserts data continuity and health, and auto-rolls-back on failure.
4. `magpie-ctl migrate` in this release is a data-format **stamp only**
   (`PRAGMA user_version` 0 -> 1). It establishes the migration mechanism and
   fail-closed-on-downgrade behavior for future real migrations; it does not
   transform artifacts.

Verified end-to-end on a real v0.1.6 install: `update` to bundled 0.2.0 with
byte-identical data, and auto-rollback on an injected failure.

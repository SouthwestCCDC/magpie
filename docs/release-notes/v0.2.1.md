## Highlights

v0.2.1 is a bug-fix and documentation release on the v0.2 line. It changes
no data format and needs no action before upgrading: swap in this release's
`docker-compose.yml` (or bump your pin) and restart.

## Fixes

- **`MAGPIE_ALLOWED_CIDRS` accepts more than one range** (#612). In v0.2.0 a
  list such as `10.0.0.0/8,192.168.1.0/24` reached the bundled Caddy as one
  argument and Caddy refused to start, so only a single CIDR worked.
  Comma-separated is the documented form; whitespace and mixed separators are
  also accepted. An empty value still disables the allow-list.
- **Fresh installs say where the admin token went** (#618). `magpie-deploy.sh
  install` used to print "Database already initialized" on a brand-new
  install, because the container initializes the database on first boot. It
  now names the configured `MAGPIE_ADMIN_TOKEN_SINK` and, for the `file`
  sink, shows `sudo cat <data dir>/admin-token`. "Database already
  initialized" now only appears when a database already existed.
- **No more "Caddyfile is not formatted" warning at every start.** The
  bundled Caddyfile is now `caddy fmt`-clean, and CI enforces it.

## Documentation

The onboarding docs were reworked: a "Why Magpie" overview, a Quick Start
verified end to end, an architecture page, and a single configuration
reference (`docs/configuration.md`). Install snippets now download from
`releases/latest`, treat the release `docker-compose.yml` as the primary
deployment path, and describe `magpie-deploy.sh` as optional.

## Upgrading

From v0.2.0 there is no migration: the data directory is reused as-is.
v0.2.0 clients keep working against a v0.2.1 server (and the reverse),
because the compatibility check only compares major and minor versions.

If you work around #612 with a single CIDR, you can now list every range you
need.
